## Основные понятия

```
Producer → [Topic → Partition 0] → Consumer Group
                 → [Partition 1] →
                 → [Partition 2] →
```

- **Topic** — категория сообщений
- **Partition** — физическое разбиение топика (параллелизм + упорядочивание)
- **Offset** — позиция сообщения в партиции
- **Consumer Group** — группа консьюмеров (один консьюмер на партицию)

## Партиционирование

### С ключом
```java
producer.send(new ProducerRecord<>("topic", "card-123", message));
```
Ключ → hash % numPartitions → одна партиция.

**Гарантия:** все сообщения с одним ключом идут в одну партицию → строгий порядок для ключа.

**Пример:** ключ = номер карты → все события по одной карте в одной партиции → правильный порядок операций.

### Без ключа
По умолчанию — **round-robin** (по очереди в разные партиции).  
✅ Равномерное распределение  
❌ Нет гарантии порядка между партициями

## Семантика доставки

| Семантика | Описание | Риск |
|---|---|---|
| **At most once** | Максимум 1 раз | Сообщение может потеряться |
| **At least once** | Минимум 1 раз | Сообщение может задублироваться |
| **Exactly once** | Ровно 1 раз | Нет потерь и дублей (самое сложное) |

### Exactly once в Kafka
Требует:
- `enable.idempotence=true` у продюсера
- Транзакции на стороне продюсера
- `isolation.level=read_committed` у консьюмера

## Retention

```properties
# По времени (по умолчанию 7 дней)
retention.ms=604800000

# По размеру
retention.bytes=1073741824

# Compaction (хранить только последнее значение для каждого ключа)
cleanup.policy=compact
```

## Consumer Group Rebalance

При добавлении/удалении консьюмера из группы — происходит rebalance: перераспределение партиций.

Во время rebalance — потребление останавливается (Stop-The-World для группы).

## Event Streaming

Каждая точка данных = событие.  
**Event Stream** — непрерывный поток событий/точек данных.

Kafka = платформа event streaming:
- Хранение событий как журнала (лог)
- Обработка в реальном времени
- Replay — возможность перечитать события с любого offset
