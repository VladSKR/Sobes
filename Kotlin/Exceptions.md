# Kotlin — checked exceptions

## За две минуты

- Kotlin не требует объявлять или ловить checked exceptions на уровне языка, хотя Java-библиотека может их бросить.
- Обрабатывай конкретный сбой там, где можешь восстановиться, а не проглатывай все исключения.

---

## Почему нет обязательной проверки checked exceptions

Kotlin не требует `throws` и не заставляет ловить исключение при вызове метода. Это решение дизайна языка уменьшает количество обязательного шаблонного кода; оно **не означает**, что checked exception Java-библиотеки исчезнет во время выполнения. Для Java caller у Kotlin-функции при необходимости используют `@Throws(IOException::class)`.

Проверяемый exception в Java сам по себе не «нарушает LSP»: некорректно объявлять это доказанной причиной отказа Kotlin от механизма. В обработчике ловим конкретную ошибку, когда можем восстановиться, и не проглатываем сигнал отмены корутины.
