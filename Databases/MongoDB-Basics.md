# MongoDB — минимум для Senior-интервью

## За две минуты

- MongoDB хранит BSON-документы в коллекциях; модель вложений и ссылок выбирают по запросам.
- Индекс ускоряет выборку ценой записей и места; `explain()` показывает, используется ли он.
- `$lookup` существует, но плохо выбранная схема и отсутствие индекса могут сделать соединение дорогим.

---

MongoDB хранит документы BSON в коллекциях. Документ может содержать вложенные объекты и массивы; модель выбирай под запросы и частоту изменения связей, а не по правилу «NoSQL быстрее SQL». Документ даёт удобный атомарный контур для своих полей; многодокументные транзакции существуют, но требуют отдельной оценки схемы и нагрузки.

```javascript
db.users.find({ age: { $gte: 18 }, status: { $in: ["ACTIVE", "NEW"] } })
db.users.createIndex({ status: 1, age: 1 })
db.orders.aggregate([
  { $match: { status: "PAID" } },
  { $group: { _id: "$customerId", total: { $sum: "$amount" } } }
])
```

`$lookup` соединяет данные из другой коллекции, но не означает, что можно бесконтрольно проектировать relational joins; производительность зависит от объёма, индекса на связываемом поле и плана. `explain()` показывает использование индекса и объём просмотренных документов. Индексы улучшают выборки и замедляют записи; выбирай по частым предикатам и сортировкам.

**Вопросы:** чем документ отличается от строки таблицы? Когда вложить объект, а когда хранить ссылку? Как проверить медленный `find`? Это был реальный пробел на скрининге, поэтому запомни прежде всего модель, `find`, индекс, aggregation pipeline и ограничения `$lookup`.
