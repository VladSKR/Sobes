# Redis: cache и атомарные операции

Redis подходит для cache, счётчиков, короткоживущих ключей и некоторых координационных задач. TTL ограничивает срок жизни; eviction policy применяется при нехватке памяти, а не заменяет TTL. `cache-aside`: сначала cache, при miss — DB и заполнение cache; при изменении source of truth продумай инвалидирование, устаревшие значения и stampede.

```text
GET → miss → DB → SET EX
write DB → invalidate key
```

Пара `EXISTS` затем `SET` неатомарна при конкуренции; `SET key value NX EX ...` атомарно создаёт ключ, если его нет. Для финансового инварианта одним Redis-lock нельзя заменять уникальные ограничения и транзакционные проверки в БД; при failover/replication могут быть тонкости. Для лимита запросов `INCR` атомарен для одного ключа, но установка TTL и сложные составные операции требуют продуманного атомарного сценария.
