# PostgreSQL: нормализация, типы, JOIN

## За две минуты

- Нормализация уменьшает аномалии изменения данных; денормализацию выбирают под измеренный запрос и поддерживают согласованность копий.
- В PostgreSQL `text` и `varchar(n)` похожи по хранению; ограничение длины — часть контракта, когда оно реально нужно.
- `JOIN` без уточнения означает INNER JOIN, а LEFT JOIN сохраняет строки левой таблицы.

---

**Нормализация:** 1NF — атомарные значения в рамках выбранной модели; 2NF — неключевые поля зависят от всего составного ключа; 3NF — нет транзитивной зависимости неключевого поля от ключа через другое неключевое. Сначала проектируй корректную модель, потом осознанно денормализуй под конкретные запросы, измерив цену синхронизации копий.

В PostgreSQL `text` и `varchar(n)` имеют схожее хранение и производительность в типичных случаях; `varchar(n)` полезен, если ограничение длины — часть контракта. `char(n)` дополняет пробелами до фиксированной длины; без особой причины не выбирай его для имён и произвольных строк.

`JOIN` без префикса означает `INNER JOIN`. `LEFT JOIN` сохраняет строки слева и заполняет отсутствующие справа null; условие по правой таблице в `WHERE` может неявно убрать такие строки. Self join — соединение таблицы с ней самой с разными alias.

```sql
SELECT e.id, manager.id AS manager_id
FROM employees e
LEFT JOIN employees manager ON manager.id = e.manager_id;
```

Это базовые вопросы, но по фидбеку интервью требовали более чётких формулировок: не путай self join с отдельным видом SQL JOIN, а PK — с физическим порядком хранения. Индексы и планы — [[Databases/PostgreSQL-Interview-Gaps]].
