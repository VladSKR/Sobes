# Метрики, перцентили и разбор инцидента

При методе ближайшего ранга p99 для 1000 измерений — 990-е значение после сортировки. Если 990 запросов заняли 10 мс, а десять — 5000 мс, среднее будет 59,9 мс, p99 — 10 мс, p99.9 — 5000 мс. Алгоритм расчёта и границы гистограммы могут изменить оценку. Выбирай перцентиль под долю запросов, важную для цели сервиса.

p50 — медиана задержки, p95/p99 показывают хвост. Средняя latency скрывает редкие многосекундные запросы; сравнивай per-endpoint, status, downstream и нагрузку. У метрики нужны понятные labels, но user ID в label создаёт неконтролируемую кардинальность.

При инциденте: начни с пользовательского симптома и окна времени → RPS/errors/latency/saturation → traces с correlation ID → медленные SQL и EXPLAIN → pool и очереди → recent deploy/config. Сопоставляй метрики с бизнес-инвариантами: число stuck pending orders, outbox lag, возраст reservations, расхождение ledger/balance. Разделяй обнаружение, временное ограничение ущерба и постоянное исправление.

[Переводы и заказы](../Architecture/Money-Transfer-and-Order-Design.md) показывают применение этих метрик в system design.

## От графика к гипотезе

Пусть p99 checkout вырос, хотя среднее и RPS почти прежние. Отфильтруй по endpoint и успешным ответам, затем сравни latency приложения и зависимостей на одном временном интервале. Trace может показать 5 мс выполнения SQL и 700 мс получения соединения. Такая картина направляет проверку на насыщение пула и долгие операции, удерживающие connection. Если следов недостаточно, добавь отдельно измеряемые интервалы ожидания и исполнения.

При расчёте перцентилей по нескольким pod агрегируй совместимые histogram buckets, затем вычисляй перцентиль. Среднее от p99 каждого pod обычно не совпадает с p99 совокупного трафика. [Prometheus: histograms](https://prometheus.io/docs/practices/histograms/)

## Two-Minute Drill

- p95 — значение, ниже которого около 95% измеренных запросов; среднее может скрыть медленный хвост.
- При инциденте сопоставь errors/latency/RPS, насыщение пула, SQL и время изменения системы.
- Для заказов следи за stuck pending, outbox lag и долей неуспешных платежей.

**Проверь себя.** Почему среднее от p99 двух pod не даёт p99 всего сервиса?

Перцентиль зависит от общего распределения и объёма трафика каждого pod. Агрегируй измерения или совместимые histogram buckets.
