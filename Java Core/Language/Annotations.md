# Аннотации Java

Аннотация хранит метаданные о программе. По ним компилятор или библиотека может выбрать действие. Разберём, когда сведения доступны и кто их использует.

## Пример

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Audited { }

class Service {
    @Audited
    void transfer() { }
}
```

`RUNTIME` позволяет искать `@Audited` у метода через reflection во время работы программы. `SOURCE` остаётся только в исходном коде и не попадает в class-файл; `CLASS` попадает в class-файл, но не обязана быть доступной обычному reflection API во время выполнения. Это не значит, что `@Audited` уже ведёт audit: нужен код, который обнаружит её и выполнит действие. [[Spring/Core/Reflection]].

## От объявления до обработчика

Компонент аудита может проверить `method.isAnnotationPresent(Audited.class)` или использовать аннотацию в AOP. Для генерации кода на этапе компиляции используется annotation processing, поэтому доступность в runtime требуется только обработчикам, работающим во время выполнения.

## Two-Minute Drill

- Аннотация — метаданные на классе, методе или поле; сама по себе она не запускает поведение.
- `@Target` ограничивает место применения, `@Retention` — как долго метаданные сохраняются.
- Код, который читает аннотацию (компилятор, процессор, Spring), придаёт ей смысл.

**Проверь себя.** Будет ли метод с аннотацией Audited автоматически записан в аудит?

Нет. Нужен обработчик, который обнаруживает аннотацию и выполняет запись.
