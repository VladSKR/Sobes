# String, pool, final и immutable

## За две минуты

- String неизменяем, поэтому его безопасно использовать как ключ и разделять между потоками.
- `==` сравнивает ссылки, `equals` — содержание.
- `final` ссылка сама по себе не делает её объект immutable.

---

`String` неизменяем: операции вроде `replace` возвращают новый объект; это упрощает использование как ключа карты и совместный доступ из потоков. Строковые литералы интернируются и могут ссылаться на один объект из pool; `new String("x")` создаёт отдельный объект. Для сравнения текста используй `equals`, `==` сравнивает ссылки.

`final` у ссылки запрещает переназначение ссылки, но не делает изменяемый объект immutable. У собственного immutable-класса поля должны быть скрыты, состояние полностью построено до публикации, а изменяемые вложенные объекты — скопированы при входе/выходе. Про защитные копии коллекций — [[Java Core/Collections/Choosing-and-Immutability]].

В интервью ты уверенно говорил про `String`, но важно не смешивать `String immutable` с «любой `final` объект неизменяем».
