# Как JVM запускает и исполняет программу

## От исходника к выполнению JVM

`javac` компилирует исходник в байткод `.class`. Команда `java` запускает JVM, которая загружает нужные классы и начинает выполнение с точки входа. **HotSpot** — реализация JVM. **JIT (just-in-time compiler)** — её компилятор, который строит машинный код во время работы программы.

## Зачем HotSpot компилирует во время работы

Сначала HotSpot может интерпретировать байткод и собирать профиль. Например, он видит, что метод обработки заказа вызывается регулярно и что конкретная реализация интерфейса встречается почти всегда. В типичной многоуровневой конфигурации компиляторы C1 и C2 позволяют обменять время компиляции на глубину оптимизации. JIT может встроить вызов, убрать ненужную аллокацию или оптимизировать цикл. При изменении предположений JVM может деоптимизировать код и продолжить выполнение в менее специализированной версии.

Внутри долгого цикла переход тоже возможен. **OSR (on-stack replacement)** позволяет перейти из выполняющегося кадра в скомпилированную версию, не дожидаясь выхода из метода. Например, при одном вызове метода с миллионами итераций код может стать горячим по числу проходов цикла.

## Запуск и параметры

```bash
javac Main.java
java Main
java -jar app.jar
java -Xms256m -Xmx1g -XX:+UseG1GC -jar app.jar
java -XX:+PrintFlagsFinal -version
```

`-Xms` и `-Xmx` задают начальный и максимальный heap. Параметры после `-jar app.jar` получает приложение (например, `--server.port=8080` у Spring Boot). Не путай их с флагами JVM перед `-jar`.

## Что проверить, если приложение не стартует

При `UnsupportedClassVersionError` рантайм обычно старее версии байткода. Например, `javac --release 17 Main.java` создаёт класс и ограничивает использование API выбранным релизом. Если `java Main` сообщает, что основной класс не найден, проверь пакет, имя и classpath. При `java -jar app.jar` точку входа задаёт manifest или упаковщик приложения. ## Two-Minute Drill

- У каждого потока свой стек вызовов; heap разделяется потоками. Metaspace содержит метаданные классов, CodeCache — JIT-скомпилированный код.
- JIT ищет часто выполняемый код и компилирует его в машинный, оптимизации могут быть отменены при изменении предположений. Это не то же самое, что GC.
- GC начинает поиск живых объектов от GC roots; G1 и ZGC различаются способом работы и длительностью пауз. Выбирай по измерениям.

**Проверь себя.** Может ли JIT оптимизировать метод, вызванный всего один раз? Да. Например, долгий цикл проходит порог горячего кода, и OSR позволяет продолжить на скомпилированной версии внутри этого вызова.
