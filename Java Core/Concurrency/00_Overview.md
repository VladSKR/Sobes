# Многопоточность в Java

У сервиса одновременно выполняются несколько запросов. Один поток ждёт ответ базы данных, другой в это время обрабатывает заказ. Если оба меняют один остаток на складе, результат зависит от того, как они координируют доступ. В этой главе разберём, откуда берётся одновременное выполнение и как наблюдать за отдельным потоком.

## От процесса к потоку

Процесс даёт приложению адресное пространство и системные ресурсы. Поток — последовательность выполнения внутри процесса со своим стеком вызовов. Два потока могут получить ссылки на один объект в куче. Их локальные ссылки принадлежат разным вызовам, а поля общего объекта остаются общими.

**Конкурентность** означает, что несколько задач продвигаются за один промежуток времени. На одном ядре планировщик может переключаться между ними. **Параллелизм** означает одновременное исполнение инструкций на разных вычислительных ресурсах. Один и тот же код с гонкой может сломаться в обоих случаях. Например, между чтением остатка и записью нового значения планировщик может передать управление другому потоку.

`Runnable` описывает работу с методом `run()`. `Thread` представляет поток выполнения. Вызов `thread.run()` напрямую ведёт себя как обычный вызов метода текущим потоком. Вызов `thread.start()` запускает отдельный поток, который затем вызывает `run()`. Для отправки многих задач есть executor. Его очередь и получение результата разобраны в [главе про задачи](Executors-CompletableFuture.md).

## Состояния и ожидание

| Состояние Java | Что происходит |
|---|---|
| `NEW` | Поток создан, `start()` ещё не вызывали |
| `RUNNABLE` | Поток исполняется или может исполняться. Java также может показывать его так во время некоторых системных операций |
| `BLOCKED` | Поток ждёт входа в монитор `synchronized` |
| `WAITING` | Ждёт события без заданного срока, например завершения другого потока через `join()` |
| `TIMED_WAITING` | Ждёт с ограничением времени, например в `sleep()` |
| `TERMINATED` | `run()` завершился успешно или с необработанным исключением |

Состояния ожидания могут повторяться. Например, после получения монитора поток возвращается в `RUNNABLE`, а при следующем захвате снова может ждать. Состояние Java из дампа потоков и состояние потока с точки зрения ОС описывают разные уровни.

## Отслеживание исключений в потоках

```java
Thread worker = new Thread(() -> {
    throw new IllegalStateException("job failed");
}, "worker");
worker.setUncaughtExceptionHandler((thread, error) ->
    System.err.println(thread.getName() + ": " + error));
worker.start();
worker.join();
```

Исключение раскручивает стек того потока, в котором возникло. Обработчик получает ошибку рабочего потока. `join()` возвращает управление после его завершения. Если исключение нужно передать инициатору работы вместе со статусом, используй [Future](Executors-CompletableFuture.md#future-и-блокирующее-ожидание). При `submit()` стандартный пул сохраняет результат или ошибку в `Future`. У `execute()` такого объекта нет.

## Передача результата между потоками

Если фоновая задача вычислила число, инициатор может дождаться потока через `join()` и только потом прочитать результат из общей структуры. Здесь ожидание означает, что инициатор не может продолжить свою текущую работу до завершения. Для результата с ошибкой удобнее `Future<T>`. Для продолжения без выделенного ожидающего потока подходит цепочка стадий. Начинай со способа взаимодействия, затем выбирай API.

## Two-Minute Drill

- Поток выполняет код со своим стеком вызовов. Ссылки в разных потоках могут вести к одним и тем же данным в куче.
- Конкурентность возможна на одном ядре через переключения. Параллелизм использует одновременное исполнение, и оба режима допускают гонки.
- `start()` создаёт отдельное выполнение, `run()` напрямую остаётся обычным вызовом. `join()` ждёт завершения потока.
- `BLOCKED` в дампе Java означает ожидание монитора. Другие способы ожидания дают другие состояния.
- Для `Thread` необработанное исключение наблюдает `UncaughtExceptionHandler`. Для задачи, отправленной через `submit()`, проверяй `Future`.

**Проверь себя.** Может ли поток `main` после `worker.join()` продолжить работу, если `worker` упал? Да, `join()` ждёт завершения. Чтобы узнать его причину, нужен отдельный канал, например результат `Future`.
