# Рефлексия в Spring

## Пример

```java
class UserService {
    @Autowired private UserRepository repository;
}
```

Во время создания bean Spring находит поле с `@Autowired` и внедряет зависимость. Для определения кандидата контейнер умеет читать метаданные class-файлов, не загружая каждый класс ради поиска; при работе с конкретным экземпляром использует механизмы reflection/метаданных. Позже AOP-прокси может перехватить внешний вызов метода `@Transactional`: это не «рефлексия автоматически открыла транзакцию», а работа interceptor вокруг метода. См. [[Spring/Core/Transactions-and-JPA]] и [[Spring/Boot/Internals]].

## Метаданные, внедрение, вызов

Аннотация `@Autowired` сама ничего не исполняет. При создании экземпляра компонент Spring обнаруживает помеченную точку внедрения, просит контейнер подобрать объект по типу и другим условиям, затем вызывает конструктор, сеттер или устанавливает поле. Кандидатов для component scanning можно обнаружить чтением байткода до загрузки класса. В этом состоит разница между проверкой метаданных и работой с экземпляром.

В приложении с Java modules доступ к закрытым членам может ограничиваться правилами модулей. Если зависимость есть в публичном конструкторе, класс проще создать и проверить напрямую. Прокси нужен на другом этапе: он добавляет поведение к уже выбранному вызову. [Определения бинов и запуск](../Boot/Internals.md)

## Two-Minute Drill

- Reflection позволяет узнать класс объекта, посмотреть его поля/методы/аннотации и работать с ними во время выполнения.
- Spring читает метаданные классов и аннотаций при построении контейнера и может использовать reflection для внедрения зависимостей.
- AOP-прокси — отдельная идея: объект-обёртка перехватывает вызов метода, например для транзакции.

**Проверь себя:** зачем Spring вообще читает аннотации? Чтобы построить определения бинов и применить соответствующую конфигурацию/обработку.
