# Уровни тестирования

## За две минуты

- Unit тестирует небольшую логику быстро и изолированно.
- Integration проверяет взаимодействие реальных компонентов, например репозитория с PostgreSQL.
- E2E проводит сценарий целиком через входной API; тест дороже и медленнее, зато проверяет соединение слоёв.

## Пример: создание заказа

| Уровень | Что проверяем |
|---|---|
| Unit | Сервис вычисляет итог и не принимает отрицательное количество товара |
| Integration | Сервис и репозиторий вместе сохраняют заказ и ограничения БД работают |
| E2E | HTTP POST создаёт заказ, а последующий GET показывает его состояние |

«Пирамида» напоминает о цене большого числа E2E тестов, а не предписывает процентное соотношение. Если ошибка возникает на границе DB/Kafka, один только unit с моками её не обнаружит. Выбирай уровень по риску, а не по форме красивой диаграммы.

**Проверь себя:** какой тест выявит, что SQL ограничение UNIQUE не создано? Интеграционный с настоящей схемой БД.
